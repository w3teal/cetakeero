# cetakeero

> Caution: Slop generated by OpenCode.

A Flutter app for printing images on standard paper sizes.

## Features

- Select **one or multiple images** at once via the native file picker, or
  **drag and drop image files** straight from your file manager into the images
  panel to add them
- The images panel shows each image **as a miniature page that follows your
  print settings** — paper size, orientation, image fit and margin are
  previewed exactly like the printed result
- A **zoom slider** (60–300 px) resizes those page thumbnails; images wrap
  downward as you zoom
- **Drag to reorder** images, e.g. drag an image to slot #1 to print it first
- **Check thumbnails** to select images. The toolbar below the zoom slider has
  **Select all** / deselect, **Delete**, and **Add to grid**
- **Group images onto one page**: check a few images and press
  **Add to grid** — they merge into a single grid page whose rows × cols
  layout and inter-cell **gap** (0–12 mm) you control from the toolbar; drag a
  cell out to promote it back to its own page, drag a cell or checked batch in
  to add it to the grid
  - Row × column dimensions are validated: they must always fit every image
    already in the grid
  - **Grid drag mode** toggle next to **Select all** switches between two drag
    behaviours: in page mode you drag whole pages (reorder) — grids count as
    pages, so dragging one grid onto another reorders them without merging;
    in grid mode cell long-press handles everything — re-sort cells onto
    other cells, pull a cell out to its own page (drop it on the blank
    space), move cells between grids, drag standalone images onto grid cells,
    and drop an image onto another image to turn both into a new grid
  - A grid that is left holding only one image automatically becomes a
    standalone image page again
  - **Ungroup** splits a selected grid back into its own single pages
  - With several grids selected the grid toolbar hides and they are treated
    like plain images; **Add to grid** then only ever creates new grids from
    standalone images
- A **page count** sits under the Images title
- A **theme picker** in the title bar: choose one of the four catppuccin
  flavors (latte, frappe, macchiato, mocha) and an accent color from it; the
  choice is remembered across restarts
- Choose the **paper size** (A0–A4)
- Choose the **page orientation** (portrait or landscape)
- Choose the **image fit** (applies to every image, including grid cells):
  - **Contain** – the whole image is visible
  - **Cover** – the image fills the page and crops the edges
- Set the **page margin** from 1 to 50 mm
- A big **Print** button sends the job to the system printer dialog

The print dialog opens **pre-seeded with the same page size and margin** chosen
in the app, and the PDF is generated with exactly the same page size, margin and
image fit as the thumbnails — so the printed result matches the on-screen
preview with no scaling or extra driver margins.

## How it works

Each image prints on its own page; images grouped into a grid share one page,
tiled in the chosen rows × cols layout. The PDF is generated then handed to the
platform print dialog (`package:printing`), which supports printers on Android,
iOS, macOS, Windows, Linux and web print.

> Note: this repo vendors a small patch of the `printing` plugin
> (`third_party/printing`, enabled via `dependency_overrides`) so the Linux
> (GTK) print dialog honours the page size passed by the app instead of
> resetting to the printer's default page size.

## Development

```sh
flutter pub get
flutter test
flutter analyze
flutter run -d linux
```

Note: on Linux, printing requires CUPS (`libcups2-dev` and a running `cupsd`)
and the GTK unix-print development files (`gtk+-unix-print-3.0`).
